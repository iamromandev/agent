# AGENTS.md

Agent: placeholder project (purpose TBD) — FastAPI API (Python 3.15) + Typer CLI + React SPA + OpenTofu infra. Same architecture as `exateks/auth`. `api/`, `cli/`, `ui/` and `infra/` are self-contained; the root `makefile` only delegates.

## Commands (run from the repo root)

| Command | What it does |
| --- | --- |
| `make check` | API and CLI `ruff check --fix` + `ty check`, then UI `tsc`. **Fixes Python files**; does not check UI formatting. |
| `make -C api check-ci` / `make -C cli check-ci` | Lint + types without fixes — what CI runs. Use this before committing. |
| `make test` | API and CLI pytest suites. |
| `uv run --directory api pytest tests/path/test_file.py::test_name -q` | One API test. |
| `bun run --cwd ui web:test` | UI tests (`bun test test/`). |
| `bun run --cwd ui web:format` / `web:format.check` | Prettier write / check. |
| `make api-up` / `make api-migrate` | Start Postgres + API containers / run migrations in the container. |
| `make cli-run ARGS="health check"` | Run the CLI. |
| `make cli-run` (bare `agent`) | Open the terminal coding agent (Textual TUI); needs Ollama at `AGENT_OLLAMA_URL`. Its workspace is the directory it runs in: `cli/` for `make cli-run` and `cd cli && uv run agent`. For another folder run `uv run --project <repo>/cli agent` from it (`--project` keeps the cwd; `--directory` changes it). |
| `make cli-run ARGS='-p "..."'` | Headless mode: one turn without the UI, final reply on stdout (see the "Headless mode" bullet). |
| `make -C cli eval` (or `make cli-eval`) | Real-model smoke test (`cli/evals/`, needs Ollama; not in `make test` or CI): four fixed tasks (`find`, `rename`, `rules`, `command`) run headlessly in temp copies of `cli/evals/fixtures/sample`, `EVAL_RUNS` times each (default 3; also `EVAL_TASKS=a,b`, `EVAL_TIMEOUT` seconds default 300, `EVAL_KEEP=1`). Prints a table and writes `cli/.eval/<UTC timestamp>.json`; without Ollama it prints a skip line and exits 0. Isolation covers agent config, data, sessions and the workspace copy; `bash` runs with the real environment, so tasks allow only fixed commands (exact-match rules, no prefix approvals) and a test checks each task refuses a chained command. |
| `make cli-tool-install` / `make cli-tool-uninstall` | Install `agent` on the PATH as an editable uv tool (`agent-cli`) / remove it. Rerun the install after dependency changes or moving the checkout. |
| `uv run --directory api pre-commit install` | Install hooks once; mirrors CI (`ruff check`, `ty`, `prettier --check`). |

- Prefer `make api-up` over raw `docker compose up`: the compose project name is pinned to `agent`.
- Do not run `ruff format`: the formatter rewrites valid `except (A, B)` into invalid Python. `make`/CI/pre-commit use `ruff check` only.

## Setup / test prerequisites

- Python is pinned to exactly `3.15.0`; use `uv` for all Python tooling. Bun handles `ui/`.
- Copy `api/.env.example` to `api/.env` before tests or dev: `Settings` is instantiated at import, so even hermetic tests fail without it.
- Compose publishes Postgres on **5410** and the API on **8000**.
- `.env`, `uv.lock` and `bun.lock` are gitignored, so CI resolves fresh dependencies; direct deps are pinned in `pyproject.toml` / `package.json`.

## Architecture that is not obvious from filenames

- API entrypoint is `src.main:app`. Routers mount at the root (`/health/check`); there is no `/api` prefix. The Vite dev proxy owns `/api/*` and strips `/api` on the way out.
- Layering is `route/` → `service/` → `data/repo/`; Pydantic schemas live in `data/schema/`, enums in `data/type/`, domain logic in `lib/`, FastAPI dependencies in `deps/`. API tests mirror `src/`.
- Services are provided by `get_<name>_service` factories in `src/service/__init__.py`; repos by `get_<name>_database_repo` in `src/data/repo/__init__.py`, with interfaces in `<domain>/interface/` and implementations in `<domain>/<name>_db.py`.
- Every response is an envelope: `Success.ok(data=...).to_resp()` (`src/core/success.py`) or a raised `Error` (`src/core/error.py`), rendered by `init_global_errors`.
- Models subclass `IdBase` → `LinkBase` → `Base` in `src/core/base.py`; repos subclass `BaseRepo`; services `BaseService`; schemas `BaseSchema`.
- The CLI keeps the same shape: commands in `cli/src/command/`, and only `cli/src/client/` makes HTTP calls (`api.py` for the API, `ollama.py` for Ollama). Bare `agent` opens the coding agent: `cli/src/engine/` is the UI-free core (loop, tools, provider contract; no `textual`/`httpx` imports, enforced by `cli/tests/test_boundaries.py`) and `cli/src/tui/` is the Textual app on top of it. Conversations are saved under `~/.local/share/agent/sessions/` (`AGENT_SESSIONS_DIR`, or `$XDG_DATA_HOME/agent/sessions`; never in the workspace), one JSONL file per session, kept without limit: `agent --continue` resumes the latest for the folder, `agent --resume [id-prefix]` picks one or resumes by id, `/sessions` switches inside the app, `/new` starts a new session, `/compact` shrinks the context (also automatic at `AGENT_COMPACT_AT` of the window), `/undo` steps back one turn at a time in this run (restores what `write`/`edit` changed, deletes files the turn created, skips files changed since; bash and terminal effects (`term_start`/`term_stop`) are not undone, only counted; the prompt returns to the input box; compaction, `/new`, `/clear` and session switches discard the undo history), and `/clear` is now the same as `/new` (it used to only empty the screen). `cli/src/engine/session/` is the storage; every test runs with its own sessions folder. Instructions come from every `AGENTS.md` between the git root and the launch folder (a symlinked file, or one that is a protected path, is not read and the instructions notice names it as refused), limited to `AGENT_INSTRUCTIONS_SHARE` of the window, and `/init` has the model write one for the launch folder.
- The TUI has a terminal pane: `ctrl+t` shows or hides it (the first time it starts a `shell` tab running `$SHELL` in the workspace) and moves focus between the terminal and the chat input; `ctrl+\` also returns to the chat, from inside full-screen apps too. `ctrl+pageup`/`ctrl+pagedown` switch tabs (clicking a tab works too), and `ctrl+w` closes the tab of an exited terminal, or any tab while the tab bar has focus (stopping it first); while a running terminal has focus, `ctrl+w` and every other key (Tab, Esc, `ctrl+c`) go to its process, except `ctrl+t`, `ctrl+\`, `ctrl+pageup` and `ctrl+pagedown`, which the app takes even then. Some terminals (macOS Terminal.app) do not send `ctrl+pageup`/`ctrl+pagedown`, so there tabs are switched with the mouse only. Each terminal is a pty in its own process group: `cli/src/engine/terminal/` (UI-free: pty, manager, bounded plain-text scrollback) owns them, `cli/src/tui/widgets/terminal.py` draws them with `pyte` (only `cli/src/tui/` imports it) within a per-tick time budget, so a flood of output cannot stall the app. The model gets three tools: `term_start(name, command)` and `term_stop(name)` (both need approval and are refused in plan mode) and `term_read(name, lines?)` (the last plain-text lines and the status). Terminals belong to the run: `/new`, `/clear` and session switches keep them, and every process group is stopped (SIGTERM, then SIGKILL) however the app quits. A terminal the model starts while the pane is hidden is announced in the transcript.
- Permission rules: UI-free `cli/src/engine/permissions/` (`rules.py` parse/match, `config.py` files and atomic `add_allow`, `setup.py` `prepare` + the runtime `Rules`). `~/.config/agent/settings.json` (or `$XDG_CONFIG_HOME/agent/settings.json`) and the launch folder's `.agent/settings.json` are `{"permissions": {"allow": [...], "deny": [...]}}` (other keys are kept), read once at launch; a bad file or rule is a transcript warning (a bad project file adds no deny rules either; a symlinked project file is refused, the global one may be a symlink). A rule is `tool`, `tool(value)` (the key argument, `Tool.grant_arg` / bash `command`, equals `value`), `tool(prefix*)` (only a trailing `*`) or `mcp__<server>__*`; an allow rule with a prefix matches a `bash`/`term_start` command (`SHELL_TOOLS`) only when the whole command fits `PLAIN_COMMAND` (letters, digits, space and `_./:=@%+,-`: an allow-list, because `$SHELL` may be zsh or fish), while deny rules use `Rule.denies`, which also looks at the start of every command in the line (split on `;&|`, backtick, parentheses, braces and newlines, after `lstrip`) and is best effort (`env rm`, `sudo rm`, `/bin/rm` pass); valued rules on a tool without a key argument (`read`, `write`, `edit`, MCP tools) never match and `prepare(..., keys=tool_keys(tools))` warns about them. A server name whose model name (`names.clean`) contains `__` or ends with `_` is skipped by `mcp/config.py`, so `mcp__<server>__*` cannot match another server's tools. Order in `loop.py`: deny rules first (every mode, every tool, result `denied by rule <rule> (<source>)`), then allow rules (never in plan mode), then `Grants`, then the dialog. `Rules` lives on the `Agent` next to `Grants` (not reset by `/new` or session switches) and the `task` child shares it. Project allow rules are inactive until the sha256 of the exact file bytes is in `TrustStore` (`$XDG_DATA_HOME/agent/permission-trust.json`, separate from `mcp-trust.json`, same rules: environment only, refused inside the workspace, atomic); `AgentApp._ask_trust` asks the MCP prompt and then `PermissionTrustScreen`, never both at once. "Always here" (`Choice.PROJECT`, offered when `ApprovalRequest.save_rule` is set, i.e. `Rules.can_save`, not plan mode, and `exact_rule_text` works for the call; the option is labelled `Always here: <escaped rule>`; a write/edit of `.agent/settings.json` or `.agent/mcp.json` always shows the dialog without Always or Always here) adds the exact rule to the project file and grants it for the run; it trusts the new bytes only if the file was trusted (or had no allow rules) and the bytes `add_allow` itself read (it returns `(read, new)`) are those seen at launch; if the trust store then fails, `RuleSavedNotTrusted` says the rule is saved but the next launch will ask, an unparseable, unwritable, non-regular or over-1-MiB file is never overwritten. Settings and `mcp.json` are read through `engine/fileio.py` (regular files only, `MAX_FILE_BYTES`, deep nesting is a parse failure); every rule, path or error text from a file that is shown or returned goes through `engine/text.py` `escape`. `/permissions` lists rules, sources, inactive and invalid ones and the project file state.
- Custom slash commands: `*.md` prompt templates in `~/.config/agent/commands/` (or `$XDG_CONFIG_HOME/agent/commands/`, absolute only) and the launch folder's `.agent/commands/`, read once at launch by the UI-free `cli/src/engine/commands/` (`load_commands`; no hot reload, no trust prompt). The name is the file name without `.md` (`[A-Za-z0-9_-]+`, case-sensitive); a project command replaces a global one; a name equal to a built-in (`BUILTINS` in `cli/src/tui/app.py`, which a test keeps equal to the cases of `AgentApp._command`) is skipped with a warning, so built-ins win (`model`, `skills`, `hooks` and the rest). Optional front matter (`---` first line, closed by `---`; only `description:` is read, no YAML) then the body; `$ARGUMENTS` is replaced by the text after the name, or appended after a blank line when the body has none. `/name args` sends the expanded prompt like a typed message (busy rule, plan mode and approvals unchanged; an empty prompt only warns) and the transcript shows a dim `/name (source)` label above it, with the prompt escaped (`escape` per line, tabs kept) because it comes from a file; the label is display only and is not saved, so a resumed session shows the plain prompt. Files must be regular, UTF-8 and at most 64 KiB (project symlinks refused at open with `O_NOFOLLOW`, global ones followed); problems are launch warnings (capped at 20 plus a count) with odd characters escaped, and `/help` lists custom commands after the built-ins. Typing `/` plus a name prefix (no space yet) opens `CommandSuggestions` above the input: Up/Down move, Tab or Enter complete to `/name ` without sending (except Enter on a fully typed name, which sends it with no arguments), clicking a row completes it, Esc closes it without interrupting, and it hides while the input is not focused; while it is closed these keys keep their usual meaning (`AgentApp.check_action` hands Tab and Esc to the input only while it is open).
- Skills: folders with a `SKILL.md` in `~/.config/agent/skills/<name>/` (or `$XDG_CONFIG_HOME/agent/skills/`, absolute only) and the launch folder's `.agent/skills/<name>/`, read once at launch by the UI-free `cli/src/engine/skills/` (`load_skills`; no hot reload, no trust prompt). The name is the folder name (`[A-Za-z0-9_-]+`; an optional front matter `name:` must equal it); a folder without `SKILL.md` is ignored silently, a project skill replaces a global one. `SKILL.md` starts with front matter parsed like the custom commands' (`front_matter` in `engine/commands/loader.py`, no YAML: a quoted value keeps its quotes): `description:` is required, the body is everything after the closing `---`. Only `SKILL.md` is opened (regular UTF-8, at most 64 KiB; project symlinks for `.agent`, `.agent/skills`, the skill folder or the file are refused, the folder and file by the open itself (`O_NOFOLLOW`, `SKILL.md` opened through the folder's fd); global ones followed); bundled files are never read at launch. Problems are launch warnings (capped at 20 plus a count, escaped like command warnings). When skills exist, `Agent._system` finds the `SkillTool` among its tools and adds an "Available skills" section (`Skills.section()`: `name: description`, one line, `escape_display` (non-ASCII letters stay readable; control, bidi and similar characters are written out), 200 shown characters each, never cutting inside an escape, 8,000 characters in all, the rest as `and N more skills (see /skills)`) to the main and `task` child prompts, so prompt and tool cannot disagree; with none there is no section and no tool. `skill(name)` (`cli/src/engine/tools/skill.py`; no approval, allowed in plan mode, key argument `name` for rules, also given to the `task` child) returns the body read at launch under a header with the skill's name, source and absolute folder (`escape_display`; the body itself is raw) cut to the tool output limit; an unknown name is an error listing the valid ones. Session files hold only the call and its result, so a resumed session works without the skill. `/skills` lists `<name> (<source>): <description>` (`escape_display`) and the warnings, or `No skills.`; it is a built-in, so a custom command named `skills` is skipped.
- `web_fetch` (needs approval, allowed in plan mode) lives in `cli/src/engine/tools/web.py`; its HTTP goes through `cli/src/client/web.py`, which implements the `Fetcher` contract in `cli/src/engine/web.py` (limits: `AGENT_FETCH_TIMEOUT`, `AGENT_FETCH_MAX_BYTES`; output is cut so header, body and note fit the tool output limit). "Always" on `web_fetch` covers only that exact URL (`Tool.grant_arg`), like bash per command. The client follows redirects itself (max 5, 3xx bodies never read, one overall deadline) and refuses a hop from https to http, or to `localhost`/loopback/link-local/private literal addresses unless the first URL was one; hostnames are not resolved, so a public name pointing at a private address is not caught.
- `web_search(query, limit?)` (no approval, allowed in plan mode; offered only when `AGENT_SEARCH_URL` is set; `cli/src/engine/tools/web_search.py`) queries the user's SearXNG: the `Searcher` contract and `SearchHit`/`SearchError` are in `cli/src/engine/search_web.py` (no HTTP), the httpx implementation is `cli/src/client/searx.py` (`SearxClient`: one `GET <base>/search?q=..&format=json`, redirects never followed, 2 MB body cap, one overall deadline `AGENT_FETCH_TIMEOUT`; `AGENT_SEARCH_URL` must be http(s) with a host and errors show it without userinfo or query; failures are `SearchError`, a 403 hints at enabling `json` in SearXNG's `search.formats`). `limit` defaults to 5 and is clamped to 1-10, `query` is stripped, non-empty and at most 500 characters. The tool formats the hits under a header that marks them as untrusted web data, collapses whitespace, cuts titles, URLs and snippets to their limits (snippets 300 characters) and then writes out control, format (bidi, zero-width, tag), surrogate, private-use and unassigned characters with `escape_display` (letters and punctuation of any script stay; the query is shown with the full `escape`) and the whole text to the tool output limit. The key argument for rules is `query` (`web_search`, `web_search(<query>)`; deny rules refuse it in every mode). The `task` child gets it too (`read_only_tools(fetcher, searcher)`); the SearXNG client is closed with the web client on quit.
- MCP client (stdio servers): `~/.config/agent/mcp.json` (or `$XDG_CONFIG_HOME/agent/mcp.json`) is `{"servers": {"<name>": {"command", "args"?, "env"?}}}`; a missing file means no servers and a bad file or entry is a transcript warning, never an error. The launch folder's `.agent/mcp.json` (same format) is read too and a project server replaces a global one with the same name (`merge`). Project servers never start on their own: `setup.prepare` reads both files once, and when the project file's exact bytes are not trusted for this folder the hub creates those servers `untrusted` (`McpHub(untrusted=...)`; `start()` skips them, so `connector.connect` is never called) and `AgentApp` opens `McpTrustScreen`, which lists each name and full command line (every non-printable or non-ASCII character escaped as `\xNN`/`\uNNNN`, a scrollable list, a note that files the commands run are not checked, and "overrides the global '<name>'" when a project server replaces a global one; "Don't trust" is first and highlighted, and keys are ignored for 0.5 s after it opens); Trust writes the sha256 of the bytes that were parsed to `TrustStore` (`$XDG_DATA_HOME/agent/mcp-trust.json`, else `~/.local/share/agent/`; derived only from that environment variable, never from `AGENT_SESSIONS_DIR` or any setting, because settings can come from a `.env` in the workspace; a store inside the workspace is refused for reading and writing, with a warning; atomic write; an unreadable or corrupt file trusts nothing) and starts them, while Don't trust, Escape or a stray Enter keeps them stopped for this run. Editing the file asks again; a global server of the same name is replaced even while the project's is untrusted (`/mcp` says so). `/mcp` lists every server as `<name> (<source>) <status>[: reason]` with the tool names of ready ones. `cli/src/engine/mcp/` is UI-free and SDK-free (`config.py`, `names.py`, `contract.py`, `hub.py`, `tool.py`, `trust.py`, `setup.py`); only `cli/src/client/mcp.py` imports the official `mcp` package (enforced by `cli/tests/test_boundaries.py`) and implements the `McpConnector` contract with one owner task per server (anyio scopes must be entered and left by the same task). `McpHub` is created once per run in `cli/src/tui/__init__.py` (like `TerminalManager`): `AgentApp` starts it after the session is drawn, so the input is usable while servers start, and turns its events into notices. Each tool of a ready server is offered as `mcp__<server>__<tool>` (characters outside `[A-Za-z0-9_-]` become `_`; a later duplicate is skipped with a warning); `Agent(extra_tools=hub.tools)` asks for the current MCP tools at every request, so they appear when a server becomes ready and disappear when it exits. Every call needs approval ("Always" covers that tool name only, and is revoked when that tool is no longer offered, e.g. its server exited) and `mutating = True` hides and refuses MCP tools in plan mode; `uncancellable = False` keeps Esc able to interrupt a running call (write/edit calls still run to the end). Non-text results become placeholders (`[image omitted]`), an error result stays an error, output is cut at the tool output limit, and a call gives up after `AGENT_MCP_TIMEOUT` seconds (default 60) with the server left running. A server that fails to start, does not finish starting (connect and tool list) within `AGENT_MCP_START_TIMEOUT` (default 120; `AGENT_MCP_TIMEOUT` is for calls only), or exits is a warning and its tools are withdrawn (no restart). The warning for a timed-out start can arrive about 2 s after the deadline: the SDK first closes the server's stdin and waits that long before it kills it. Servers run in their own process group with the agent's environment plus the entry's `env`; when a server ends or is closed its whole group is SIGKILLed so helper processes do not outlive it. The app closes the hub first on quit, `/new` and session switches keep it, and `hub.kill_all()` (connector-level, so also servers still starting) is the synchronous fallback after `app.run()`. It relies on a private SDK function wrapped in `cli/src/client/mcp.py`; a test fails if an SDK update removes it.
- `task(description, prompt)` (no approval, allowed in plan mode; `cli/src/engine/task.py`) runs a read-only child `Agent` (`read`, `glob`, `grep`, plus `web_fetch` when configured; role `task`, its own system prompt, no instructions notice) with a fresh context and returns only its final report to the parent, under a header that marks it as untrusted subagent data, not instructions (header included in the cut to the tool output limit); one at a time, at most `AGENT_TASK_MAX_STEPS` model calls (default 15). The child shares the parent's provider, approver and `Grants` (an "Always" given in either counts for both), records nothing (the session holds only the `task` call and its report), and its events reach the TUI as `TaskProgress(call_id, event)`, shown as lines inside the task block (child text and usage never reach the parent's transcript or context indicator; the block summary shows steps and tokens).
- `todo(items)` (no approval, allowed in plan mode; `cli/src/engine/todo.py` is the UI-free data and derivation, `cli/src/engine/tools/todo.py` the tool) keeps a checklist of at most 30 items (`content` 1-200 characters, `status` `pending`/`in_progress`/`done`); each call replaces the whole list. The list is derived from the history, not stored: it is the last valid `todo` call that has a result (`current_todos`), or `Agent.todo_base`, the list a compaction or `reset(todos=...)` carried over. So resume, `/undo` and session switches need no session-format change (`SessionStore` replays the same way into `LoadedSession.todos`). While the list is not empty and not all done, every main-agent request gets a system note with it (`render_note`, item text cut to 60 characters; the whole note stays under 2,500) just before the latest user message; it is never in `history` or the session file, and `Agent.estimate` counts it. An all-done list counts as empty. The `task` child has no `todo` and gets no note. `TodosChanged(items)` (after a successful call and after `/undo`) updates the `TodoPanel` above the input (`○`/`▸`/`✓`, text escaped, hidden when nothing is left); the app also refreshes it after `/new`, `/clear` and every resume or session switch.
- Guardrails (UI-free `cli/src/engine/guardrails/`: `config.py` settings, `paths.py` protected paths, `env.py` child environment, `setup.py` the `Guardrails` value, `sandbox.py` the macOS sandbox, `redact.py` output redaction; **protected paths bind the agent's own file tools everywhere, and `bash`, terminals and MCP servers only on macOS with the sandbox on (below); without it they can read protected paths and anything else the user can**): configured by a `guardrails` key in the same two settings files as permissions, `{"guardrails": {"sandbox": {"enabled", "network", "write"}, "protected": [...], "keepEnv": [...]}}`, read once at launch from the JSON that `permissions/config.py` already parsed (`RuleFile.data`, `PermissionSetup.global_data`/`project_data`; other keys are kept). The project file may only tighten: it may add `protected` patterns and set `sandbox.network` to `false`; its `sandbox.enabled: false`, `sandbox.network: true`, `sandbox.write` and `keepEnv` are ignored with a launch warning, and a wrong type is a warning that keeps the default (all escaped). `tui/__init__.py` builds one `Guardrails` and shares it: `ToolContext.guard` (`guard_of(ctx)` falls back to `Guardrails.off`, the built-in defaults without a workspace scan and built once per home and process, when it is `None`), `TerminalManager(guard=)`, `SdkConnector(guard=)` and `AgentApp(guard=)`; its warnings join the permission warnings and its `info` lines are shown as notices. Protected paths (`ProtectedPaths`, matched on the resolved path, case-insensitive): `~/.ssh/**`, `~/.aws/**`, `~/.gnupg/**`, `~/.config/gh/**`, `~/.docker/config.json`, `~/.netrc`, `~/.kube/config`, `~/Library/Keychains/**`, and anywhere `.env`, `.env.*` (not `.env.example`, `.env.sample`, `.env.template`), `*.pem`, `*.key`, `id_rsa*`, `id_ed25519*`, `id_ecdsa*`; a settings pattern with a `/` is a path (`~` is the home folder, a relative one matches under any folder), one without matches the file name anywhere, a pattern that names a folder (trailing `/`, or no wildcard in its last segment, e.g. `~/secrets`) also covers everything inside it, a pattern with a `..` segment or a bare `~` is ignored with a launch warning, and settings patterns are only added, never removed. Matching is on the NFC form of the path with a leading macOS `/System/Volumes/Data` removed (case-insensitively: APFS is), and also by file identity, which `(st_dev, st_ino)` recorded at launch provides only for what is named by an absolute, wildcard-free pattern or found by name: every existing file and folder such a pattern names (the built-in ones with `~` expanded, a settings pattern like `~/secrets` or `/etc/app/key`; a relative pattern or one with a wildcard in its last segment names no single place, so it has no identity), the regular files under those folders (at most 2,000 files, 5,000 folders visited and 4 levels), and the files in the workspace whose name matches a name pattern (`.env`, `.env.*` but not the templates, `*.pem`, `*.key`, `id_*`, and settings name patterns; own budget of 2,000 files, 5,000 folders and 12 levels, `.git`, `node_modules`, `.venv` and `__pycache__` are not entered); `/guardrails` says when a bound was hit. A path that is a tracked file, or is or lies in a tracked folder, counts as protected whatever its spelling (a firmlink, an unresolved symlink), and a hard link to a tracked file, made before or after launch, is protected too (not caught: a hard link to a file created after launch, to a file under a wildcard-only path pattern, or beyond the bounds). `~` means `Path.home()` and, when it differs, the account's recorded home (`pwd`; `/guardrails` lists both homes then); settings patterns are trimmed (an empty one is ignored with a warning) and a pattern ending in `/*` warns that it covers only direct children (use `/**`). `read` and `grep` also check the file they actually opened (`ProtectedPaths.is_protected_fd`: identity plus the real path the OS reports for the descriptor), so a symlink changed after the loop's path check cannot get a protected file through: the call is refused with `protected path` (a folder grep skips the file and counts it) unless the loop set `ToolContext.protected_ok` because the user allowed that call; `glob` opens no files. `write` and `edit` refuse a protected path (`protected path`, no dialog); `glob` and `grep` over a folder leave protected files out and end with `N protected files skipped` (a file counts by where it really is, so a symlink cannot hide one); a targeted `read`, `grep` of one file or `glob` whose pattern has no wildcard opens the dialog before the tool runs (`Agent._confirm_protected`: deny rules first, then the dialog in every mode, allow rules, `Grants` and Always never skip it; `ApprovalRequest.protected`/`protected_path`, `ApprovalScreen` shows `Protected path: <escaped path>` and only Allow once / Deny; a path that does not exist gets the normal not-found error; the `task` child shares the same `ctx` and approver). A prompt that is a built-in such as `/compact` or `/model` is exit 2 naming it (`BUILTINS` in `cli/src/engine/commands/builtins.py`); custom commands expand. Options: `--allow '<rule>'` (repeatable; settings-rule syntax; active for this run only, never saved, checked after the settings files' allow rules, deny rules still win; an invalid one is exit 2; `--allow`, `--quiet` and `--trust-project` need `-p`), `--quiet`, `--trust-project`, `--model`, `--continue`, `--resume <id-prefix>` (a bare `--resume` with `-p` is exit 2; an unknown id exit 2; `--continue` with no session starts a new one). Output: stdout is only the final assistant text of the turn (after Stop continuations) and a newline, nothing on failure; stderr has launch warnings and notices, one line per tool call `tool <name>: <arg, 120 characters, escaped> (<summary>)`, hook and compaction notices and `session <id> saved`; `--quiet` keeps only warnings and errors; no colour unless stderr is a terminal and `NO_COLOR` is unset. Approvals: deny rules, then allow rules (global, trusted project, `--allow`), then anything that would open a dialog (including the protected-path one) is refused with the result `User denied this call. Note: no approval in headless mode (use --allow)` and the turn goes on; "Always" is never offered. `term_start`, `term_stop` and `term_read` are not offered. Trust: untrusted project allow rules, hooks and MCP servers stay inactive, with one stderr warning per kind and no prompt; `--trust-project` (dangerous: it runs the project's hooks and servers) trusts the project settings and `.agent/mcp.json` as they are at launch for this run only and writes no trust store. Trusted MCP servers are started and waited for (up to `AGENT_MCP_START_TIMEOUT`) before the first request. All five hook events run (`SessionStart` source `startup`, or `resume` for `--continue`/`--resume`); a `UserPromptSubmit` block prints its reason and exits 1. Sandbox, child environment, redaction, compaction, `task`, todos and skills are as in the app. Sessions are saved like the app's. Exit codes: 0 done, 1 provider error, step limit, Ollama unreachable or model not installed, hook block or internal error, 2 usage error, 130 SIGINT, 143 SIGTERM (also a signal after the turn finished, and SIGTERM during launch); on a signal or any exit every child process group (bash, hooks, MCP servers) is stopped and the session file is flushed.
- Model switching: `/model` (bare, or only spaces) lists the installed models in a worker (the input stays usable; none is `No models installed.`, a list failure is one error line), reads each context length concurrently (each bounded by `SHOW_TIMEOUT`; a failure or timeout shows `?`) and opens `ModelPicker` (`cli/src/tui/screens/models.py`: name through `escape_display` cut to `NAME_SHOWN` (200) characters, size in GiB, parameters through `escape_display` cut to 12 characters, `ctx N`, each `?` when unknown, the current model marked); Enter switches, Esc changes nothing (Esc while the list still loads cancels it). The list loads without the switching claim and the input stays usable; a second bare `/model` while one loads or its picker is open is refused with a notice, and the picker is not opened if a turn or switch started meanwhile (busy line) or another dialog came up. The current-model mark is computed just before the picker opens. `/model <name>` switches directly, and both go through `AgentApp._switch_model` (the picker reuses the length it already read); only the switch takes the `/sessions`-style claim (`_begin_switch`: no switch during a turn or another switch; Enter on the picker re-checks it and shows the busy line). `--model` sets the launch model. Precedence at launch: `--model`, then a non-blank `AGENT_MODEL` (environment or `.env`), then the project key `model` in `.agent/settings.json`, then the default. The project key is read without trust (it only names a model) and is announced at launch when it decides the model; a key that is not a string, a blank one, or one not installed is a warning and the default is used (when Ollama is unreachable the installed check cannot run, so a project key is used as is). The window is the smaller of `/api/show`'s context length and `AGENT_NUM_CTX`; when the lookup fails or times out it is the cap, with a warning. A name without a tag also matches `name:latest`. The history is kept and compacted if it no longer fits the new window. A switch saves the name to the project key (`save_project_key`, trust kept like "Always here": `RuleSavedNotTrusted` and write errors are warnings, the choice then holds for the run only). The session file gets a `model` record, held until the first message is saved, so an empty session leaves no file; the `task` child follows the switch (it shares the provider). Model names in notices and warnings go through `escape_display` (the "not installed" error uses `shown_name`: full `escape`), cut to 200 characters (`NAME_SHOWN`). A launch lookup slower than `SLOW_AFTER` (1 s) prints a note on stderr naming the model being asked about.
- `/init` gives the model facts scanned from makefiles, `pyproject.toml`, `package.json` and CI, then warns about `make` and package-script commands in the written `AGENTS.md` that the scan did not find. The scan is static (it runs nothing) and stays inside the launch folder.

## Database

- Tortoise ORM + asyncpg on PostgreSQL. Migrations live in `api/src/data/db/migration/` (`0001_initial.py` is empty); `generate_schemas` is off, and `make api-migrate` runs `python -m scripts.migrate` in the container.
- Register every model in `api/src/data/db/model/__init__.py` and document it in `api/docs/model.md`.

## UI conventions

- Only `src/lib/api/*` calls `fetch`.
- No ESLint: formatting is Prettier (`.prettierrc.json`, with the Tailwind plugin) and typing is `tsc --noEmit`. Use the `@/*` aliases, not relative paths across directories.

## Infra

- `infra/` is OpenTofu in Docker: `make -C infra init ENV=<env> BUCKET=<state-bucket>`, then `plan` / `apply` with `IMAGE_TAG=<tag>`. It reuses the `exateks/infra` modules and stacks. The `prod` API image is `linux/arm64`.
